# 带符号标记排列 · 规范倒位审计页

基因组装配复核场景的纯浏览器工具：输入 3 至 7 个带符号标记组成的排列
（绝对值必须恰好为 1 至 n 且互异），在浏览器内**精确枚举全部最短倒位方案**，
给出：

- 到全正顺序 `[1, 2, …, n]` 的**最少倒位步数**；
- **最短方案总数**（bigint 任意精度，十进制展示）；
- **规范方案**：在全部最短方案中，按每步倒位 `(起, 止)` 下标对序列的字典序
  选出的唯一方案，可逐步 / 拖动滑块查看每一步的状态；
- **深度 × 区间矩阵**：每格表示“在该深度选择该区间”的最短方案数量，并标注
  - 绿：**全部**最短方案都出现；
  - 黄：**部分**最短方案出现；
  - 灰：**任何**最短方案中均未出现；
  
  点击任意格，规范轨迹联动跳转到对应深度并高亮该步区间（规范选择始终白色描边）。
- 非法输入一次性合并给出全部错误，输入文本始终保留。

**无业务后端、无持久化、无任何在线调用。** 容器只运行一个极简静态文件服务器
（`server/server.mjs`，约 100 行），计算全部在浏览器（Web Worker）内完成。

## 倒位语义

选择闭区间 `[i, j]`（1 基），将区间内标记次序反转，并同时翻转每个符号。
例：`[1,-3,-2,4]` 在 `[2,3]` 上倒位 → `[1,2,3,4]`，故最短步数为 **1**。

## 本地开发（Node 20+）

```bash
npm ci
npm test          # vitest：含对 n=3 全部 48 个排列的暴力枚举交叉验证
npm run build     # tsc --noEmit + vite 静态构建到 dist/
npm run dev       # 本地热更新开发
PORT=8080 npm run serve:static   # 用静态服务器发布已构建的 dist/
npm run smoke     # 对运行中的服务做 HTTP 冒烟（BASE_URL 可覆盖）
```

## Docker 发布

```bash
docker compose up -d --build web
# 浏览器打开 http://localhost:8080
```

宿主机端口可配置：

```bash
WEB_PORT=9090 docker compose up -d web       # 宿主机 9090 -> 容器 8080
# 或写入 .env（参见 .env.example）
```

健康检查：`GET /healthz` 返回 `200 {"status":"ok"}`；
Dockerfile 与 Compose 均声明了基于该端点的容器健康检查。

## 一次性验证服务 verify

```bash
docker compose run --build verify
```

`verify` 服务会在 `web` 健康检查通过后自动执行，并以**容器退出码**报告结果
（`docker compose ps -a verify` 可查看 `Exited (0)`）：

1. 单元测试（vitest，含独立暴力枚举交叉验证距离 / 总数 / 规范字典序）；
2. 构建检查（TypeScript 类型检查 + Vite 生产构建）；
3. 需求核查：`[1,-3,-2,4]` 最短步数为 1（唯一倒位 `[2,3]`）、
   重复绝对值被拒绝；
4. HTTP 冒烟：等待页面可访问后检查 `/healthz`、首页 HTML 与构建资源。

## 算法说明

状态空间至多 `2^n · n!`（n=7 时 645,120 个状态），每状态至多 `n(n+1)/2 = 28`
个倒位。状态压进一个整数（每个带符号标记 4 位），倒位用位运算枚举：

1. 前向 BFS（初始态出发）得到最短距离；邻居按 `(i,j)` 字典序枚举，首次到达
   各状态的父边即构成字典序最小的最短方案；
2. 反向 BFS（目标态出发，只保留位于某条最短路径上的状态），分层 DP 计算每个
   状态到目标的最短路径数（bigint）；
3. 从初始态逐层枚举“最短边”，按区间聚合格计数
   （边计数 = 前缀方案数 × 后缀方案数），得到深度×区间矩阵。

因此结果不是贪心近似——“眼前减少断点最多”的局部贪心可能错过全局最短修复、
也无法暴露等长替代路径；这里枚举的是全部最短方案。
